# Standalone compatibility review

Reviewed 2026-10-23. This is a private-protocol compatibility record, not an
Anthropic-supported API or a promise that future versions are compatible.

## Decision and minimum change

Native Claude Code `2.1.300` uses the already implemented reply wire contract.
Add that exact CLI version and supervisor version to the two existing allowlists.
No distribution-specific transport, config writer, provider adapter or binary
fallback is needed. Preserve the exact Toolbox builds `2.1.308.1355` and
`2.1.309.1365`. Version parsing accepts native `2.1.300 (Claude Code)` output as
well as the existing four-component Toolbox output, but does not truncate an
unreviewed suffix or extra version component into an allowed build.

Native/npm-distributed `2.1.293` is deliberately **not allowed**. It has a
`nextTurn` reply field, but its ping lacks `carriedPromptsFormat`. This bridge
requires protocol 1 and an explicit integer format 1. Do not relax that check
based only on a similarly named field, the installation method or semver order.
A configured `2.1.293` returns `EVERSION` with this specific reason before any
socket exchange. A reviewed CLI reaching a supervisor without the capability
returns `EPROTO`. Normal CLI-only commands retain their existing behavior.

## Static evidence

The installed macOS arm64 executables were read without executing them or
copying vendor implementation into this repository. These hashes identify the
review inputs; they are not runtime binary allowlists or platform-wide hashes.

| Native version | SHA-256 of reviewed executable |
| :--- | :--- |
| `2.1.300` | `475517caa611e3318a2f298fa071287ec98955538df78c58f709ecc01e5ae2d3` |
| `2.1.293` | `4e21122a227857da1178aca3299700c1fd7f2b77c93f12e73c2c76db796a105e` |

Independent observations for `2.1.300`:

1. The accepted control protocol is 1. Ping returns its exact version, protocol
   and `carriedPromptsFormat: 1`. Ping and list do not dispatch work.
2. The POSIX endpoint is `/tmp/cc-daemon-<uid>/<hash>/control.sock`, where the
   hash is the first eight hex digits of SHA-256 over the absolute config path.
   The native config getter normalizes Unicode to NFC before hashing. Use an
   absolute, canonical NFC config path. `TMPDIR` does not select this endpoint.
   The native Termux alternate root is outside this bridge's reviewed scope.
3. Normal control auth is `<CLAUDE_CONFIG_DIR>/daemon/control.key`, generated by
   Claude as 16 random bytes represented by 32 lowercase hex characters, mode
   0600, under a private daemon directory. The bridge only reads this key and
   never generates, repairs, prints or refreshes it.
4. A newline-delimited reply has protocol, operation, exact short ID, text,
   control auth and `nextTurn: true`. The supervisor checks auth, job availability,
   upgrade state and worker version before accepting. The worker version must
   match the supervisor. The successful ACK is exactly `ok: true, op: reply`.
5. The next-turn path uses the existing worker rendezvous connection, not PTY
   typing or a new launch. Failure to use that path is a refusal rather than a
   PTY fallback. At the REPL, it queues a human-origin ordinary prompt with next
   priority and slash-command interpretation disabled. It does not answer a
   permission dialog or a structured multiple-choice question.
6. Supervisor list returns worker records including short ID, UUID, worker PID,
   backend and worker version. The worker tracks a separate REPL PID and process
   start identity, supplied by the terminal host's child. They are not assumed
   to be equal. Existing checks require live same-user processes, equal PIDs or
   a direct parent/child pair, with start times rechecked before the only send.

The `2.1.293` binary contains the authenticated reply and next-turn handlers but
no carried-prompts-format field, including in its ping response. No compatibility
exception was added. This does not claim its own agents UI cannot reply.

## Verification levels and operator setup

Offline tests cover native version output, each reviewed CLI/supervisor pair,
matching-worker enforcement, real fixture process relationships, busy/idle
queue requests, receipt deduplication, transport uncertainty, a fresh uninitialized
config, socket hashing, missing/wrong auth and strict capability refusal. They
never run an installed Claude executable, access real credentials or contact a
model. A successful fixture or `doctor` does not prove native consumption.

Native `2.1.300` live consumption still requires operator-owned evidence. The
existing `2.1.309` Toolbox canary evidence is separate and must not be generalized
to a standalone build or another provider. Record actual native CLI and supervisor
versions, initial IDs/count, worker/REPL PIDs, auth provider, busy/idle receipt and
transcript observations, dedupe and final IDs/count before making a live claim.

For an explicitly authorized standalone canary, select the binary with
`CLAUDE_BIN`; do not change the user's PATH or installed Foxl skill. Keep all
canary commands on the same private `HOME`, absolute canonical `CLAUDE_CONFIG_DIR`
and separate `CC_SESSIONS_STATE`. An isolated config selects its own supervisor
socket and has no implicit model authentication or project trust.

1. Check the chosen binary's actual `--version` and normal auth status under that
   environment. Reuse approved provider configuration without copying secret
   tokens or silently switching auth. Provider auth and `control.key` are separate.
2. Complete native setup and trust normally. With an explicit config directory,
   Claude may use `<CLAUDE_CONFIG_DIR>/.claude.json` for global/project trust rather
   than `<HOME>/.claude.json`. Never fabricate a trust grant. If preserving an
   existing approved grant in an isolated test, retain only that exact existing
   project decision. A brand-new config without a running supervisor must fail
   `doctor`; the helper does not initialize the config or start a daemon for it.
3. Create only the explicitly authorized disposable task through the configured
   CLI. Do not test against a user's active work session. Check `doctor` against
   its exact short ID, then run the busy/idle and dedupe steps in `tests/README.md`.
4. Require the same short ID, UUID and worker/REPL identities across sends, one
   session in the isolated config, and transcript evidence for each marker. A
   receipt is acceptance, not proof of model observation. Do not retry an unknown
   outcome, even with a new request key.
5. Stop only the disposable task when authorized. Never restart or replace a
   shared supervisor, edit the user's auth/config, or revive old work to make a
   test pass. Worker/supervisor skew remains a refusal, not an upgrade request.

The code deliberately retains bounded RPC reads, kernel peer validation, private
path checks, pinned socket/peer identity and a durable reservation before a single
reply attempt. No automatic retries, stop/resume/copy delivery, daemon startup or
native registry writes were added. Non-POSIX systems, noncanonical or unsafe
paths, unsupported versions/formats, absent or stopped targets and worker skew
remain outside the send contract.

## Public references

Official documentation explains the UI and CLI semantics, not the private wire
format. Reviewed 2026-10-23:

1. https://code.claude.com/docs/en/agent-view.md
   Ordinary dispatch creates a new session; Space-peek replies to the selected
   session. Working-session replies join its native message queue. Permission
   dialogs require attach. Scripted listing uses `agents --json`.
2. https://code.claude.com/docs/en/env-vars.md
   `CLAUDE_CONFIG_DIR` configures Claude's directory. Path values must be absolute;
   settings environment values do not expand shell shorthand such as `~`.

Agent view is a research preview. Its documented UI can restart an exited session;
this bridge intentionally does not and only sends to a verified live process pair.
